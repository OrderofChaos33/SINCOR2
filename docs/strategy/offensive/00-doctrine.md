# Offensive Doctrine — Legal Competitive Strategy

**Classification:** Founder + top management only.
**Legal boundary:** Everything here must be lawful and compliant. The banned
list in `00-plan.md` is absolute. When in doubt, the action is out.

## Thesis

The most devastating legal weapon against competition is a machine that
out-executes everyone: faster shipping, better pricing, deeper partnerships,
stronger talent density, louder narrative. Offense through excellence.

We do not attack competitors. We make them irrelevant.

## The seven offensive vectors

### 1. Speed offense
Ship cadence competitors cannot match. Decision latency measured in hours,
not quarters. The 24/7 build loop is itself a weapon: every week we ship
more than they ship in a quarter, the gap compounds.

- Daily deploy capability; weekly meaningful releases.
- TOA-driven prioritization: always working the highest-leverage item.
- Parallel builders: N workstreams, zero blocking.

### 2. Talent offense
Density wins. Every hire/bar-raise increases the slope.

- Acqui-hire pipeline: identify struggling teams with great engineers.
- Contributor incentives: the agent marketplace itself attracts builders —
  every external agent that earns through us is talent we didn't have to hire.
- Open-source gravity: MIT license + real tooling pulls contributors.

### 3. Pricing offense
Use fee structure as a weapon, with real math behind it.

- 5% platform fee vs. competitors' 20–30% take rates.
- Freemium wedge: free tier that is genuinely useful, paid tier that is
  obviously worth it. No crippleware — the free tier must create love.
- Loss-leader discipline: only where lifetime value math justifies it, with
  TOA-modeled payback periods.

### 4. Partnership offense
Ecosystem lock-in through integrations competitors can't replicate quickly.

- Exclusive or first-mover integrations (x402, Base-native tooling).
- Design partnerships that become case studies that become moats.
- Every partnership announcement is a talent magnet and a customer magnet.

### 5. IP moat
- Defensive publication: publish what we don't patent so nobody else can.
- Trade secret hygiene: compartmentalize; this playbook's privacy rules apply.
- Patent posture: file where it creates leverage, not where it creates cost.

### 6. Narrative offense
Category creation. Whoever names the category sets the rules.

- "Execution Layer for the Autonomous Machine Economy" — own the phrase,
  own the category.
- Thought leadership with substance: publish real benchmarks, real numbers.
- Every claim must be verifiable. Fiction destroys narrative moats.

### 7. M&A pipeline
Criteria for targets (no names in this branch — private repo only):
- Struggling product, strong team.
- Complementary tech that would take us 6+ months to build.
- Customer base overlap with low integration cost.

## What we never do

See the banned list in `00-plan.md`. Restated briefly: no hacking, no
sabotage, no disinformation, no defamation, no manipulation, no antitrust
violations, no trade-secret theft, no impersonation. Anyone proposing such
an action is removed from this program.

## Governance

- Every offensive action gets TOA scoring before deployment.
- Every action gets auditor review (overlapping supervision).
- Quarterly doctrine review: is every vector still legal under current law?
- Founder has sole authority to deploy named-target actions.
